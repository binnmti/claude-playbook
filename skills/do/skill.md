# /do — 伝えて、任せる

ユーザーがやりたいことを伝えたら、todo.mdに整理し、自走で完了まで持っていく。

## 流れ

1. **ユーザーが話す** — やりたいことをまとめて伝える
2. **todo.mdを作る** — 話した内容を構造化して `doc/todos/todo.md` に書く。ユーザーが「自分が何を頼んだか」を見返すためのメモ。作業指示書ではない
3. **自走で実装する** — TDD、レビュー、サブエージェント活用など、やり方は全てClaudeが判断する
4. **コミットを積む** — 今いるブランチにコミットしていく。ブランチは切らない
5. **最終確認** — ユーザーとやり取りして調整する
6. **プッシュ** — OKが出たらまとめてプッシュする

## ルール

- **聞かずにやる** — 実装方針、技術選定、ファイル構成は自分で判断する。迷ったら最もシンプルな選択肢を取る
- **TDDで進める** — テストを先に書く。ただしテストが不要なタスク（設定変更、ドキュメント等）は除く
- **クロスレビューしてからコミット** — 実装が一段落したら、別のAIエージェントとレビューのキャッチボールをする（後述）
- **CLAUDE.mdに従う** — プロジェクトの規約は守る

## todo.md

ユーザーの発言を構造化したもの。最初のプロンプトを受けた時点で即座に作る。

```markdown
# やること

## ToDo
- [ ] {タスク}

## Doing
- [ ] {進行中}

## Done
- [x] {完了} (YYYY-MM-DD)
```

複雑なタスクは階層で詳細化する。シンプルなタスクは1行。
進捗に合わせてClaudeが随時更新する。

## クロスレビュー（MCP会話型）

コミット前に、MCP経由でCodex（GPT-5.4）と会話型のレビューを行う。
`mcp__codex__ask_codex` ツールを使い、修正→再レビューのキャッチボールを**収束するまで**繰り返す。

### レビュー対象の範囲

- diffはトリガー（どこが変わったかの指標）として使う
- **レビューには変更があったファイルの全文を含める** — diff単体では文脈が不足し、レビュー品質が落ちる
- ファイル単位でまとめて渡す（1ファイルずつでもまとめてでもよい。Claudeが判断する）

### フロー

1. **Claude → 変更ファイルと所見をまとめる**
   - `git diff`で変更ファイル一覧を取得
   - 変更があった各ファイルの**全文**を読む
   - バグ・設計・セキュリティの観点で自分の所見を書く

2. **Claude → Codexにレビュー依頼（Round 1）**
   - `mcp__codex__ask_codex` で以下を送る:
   ```
   あなたはコードレビュアーです。以下のファイルに変更が入りました。
   変更差分と、変更後のファイル全文、1人目のレビュアーの所見を読んでください。
   2人目のレビュアーとして、以下の観点でレビューしてください:
   - 1人目の所見への同意/反論
   - 1人目が見落としている問題の追加指摘
   - バグ、設計上の問題、セキュリティリスク
   目的は称賛ではなく欠陥発見です。findings firstで出力してください。

   ## 変更差分
   {diff}

   ## 変更後のファイル全文
   ### {file1}
   {file1の全文}
   ### {file2}
   {file2の全文}

   ## 1人目のレビュー所見
   {Claudeの所見}
   ```

3. **Claude → Codexの指摘を受けて修正する**
   - Codexの返答を読み、妥当な指摘はコードを修正する
   - 不要な指摘は理由をつけて棄却する

4. **Claude → Codexに再レビュー依頼（Round 2+）**
   - 修正後のファイル全文と、対応内容をまとめて再度送る:
   ```
   前回のレビューありがとうございます。指摘を受けて以下の修正を行いました。
   再度レビューしてください。新たな問題があれば指摘してください。
   問題がなければ「LGTM」と返してください。

   ## 前回の指摘と対応
   {各指摘への対応（修正した/棄却した理由）}

   ## 修正後のファイル全文
   ### {file1}
   {file1の全文}
   ```

5. **収束するまで繰り返す**
   - CodexがLGTMを返したら終了
   - 同じ論点で平行線になった場合は、Claudeが打ち切りを判断する
   - 回数制限は設けない。必要なだけ続ける

### ルール

- 小さな変更（設定変更、typo修正等）ではクロスレビューをスキップしてよい
- Codexへのプロンプトは日本語で統一する
- Codexの指摘を鵜呑みにしない。Claudeが最終判断者として責任を持つ
